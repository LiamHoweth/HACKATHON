# Deployment runbook (Railway)

How Still Here is deployed, configured, checked, rolled back and accessed from the iPad. Variable **names** only. Values live in the git-ignored `.env.local` (local dev), `.env.railway.local` (local copy of the deployed access code), and Railway variables. Never paste a value into chat, a doc, a commit, or a command line.

Facts below were checked on 2026-10-24 ~12:20 CT with read-only CLI calls (`railway status`, `railway deployment list`, build logs, variable names) and `scripts/railway-smoke.mjs` without `--live`.

## Architecture

- **One service.** Railway project `still-here`, environment `production`, service `api`. Public HTTPS URL: https://api-production-18038.up.railway.app. Railway terminates TLS.
- **One Next.js app** serves everything: the page, the `/api/*` route handlers (server-only provider code and keys), and the static MediaPipe assets in `public/`. There is no separate backend, database, or worker.
- **Build.** Railway uses Railpack (v0.43.0 in the last build log). It detects Node from `package.json` `engines` (`>=24 <25`; the build used 24.21.0) and runs:
  1. `npm install`
  2. `npm run build`. The `prebuild` hook runs `scripts/copy-mediapipe-assets.mjs` first, which copies the pinned `@mediapipe/tasks-vision` WASM runtime from `node_modules` into `public/wasm`. Then `next build` runs.
  3. `npm start` (`next start`, which listens on Railway's `PORT`).
- **Static assets.** `public/models/face_landmarker.task` is tracked in Git and uploaded. `public/wasm/*.js` and `*.wasm` are git-ignored and Railway-ignored, so the build regenerates them from the lockfile-pinned package. `next.config.ts` serves `/wasm/*` and `/models/*` with `Cache-Control: public, max-age=31536000, immutable` and sets security headers on every path.
- **Source of deploys.** Deploys are CLI uploads from a local checkout (`railway up`), not a connected GitHub repo. A Git push does **not** deploy.

### `.railwayignore`

`railway up` also honors `.gitignore` by default. `.railwayignore` additionally guarantees these never upload:

| Pattern | Why |
|---|---|
| `.env`, `.env.*` (except `.env.example`) | Local secrets, including `.env.local` and `.env.railway.local` |
| `node_modules/`, `.next/`, `*.tsbuildinfo` | Rebuilt on Railway |
| `ios/` | Experimental native client, outside the demo (D32) |
| `docs/screenshots/` | Large evidence images the server does not need |
| `public/wasm/*.js`, `public/wasm/*.wasm` | Regenerated by `prebuild` |

## Variables (names and meaning)

All are read server-side in `src/server/config.ts`. None use `NEXT_PUBLIC_`, so none reach the browser. Full template with defaults: [.env.example](../.env.example).

Set on Railway at 12:20 CT (names from `railway variables -s api --kv | cut -d= -f1`): `AI_PROVIDER`, `APP_ACCESS_TOKEN`, `FIXTURES_ENABLED`, `GENERATION_TIMEOUT_MS`, `OPENAI_API_KEY`, `REPLY_MODEL`, `TRANSCRIPTION_MODEL`, `TRANSCRIPTION_PROVIDER`, plus Railway's own `RAILWAY_*`. **No `ELEVENLABS_*` variables are set**, so natural voice reports "not configured" on the deployment.

| Variable | Secret | Meaning |
|---|---|---|
| `AI_PROVIDER` | no | `openai` (verified) or `anthropic` (mock-tested only) |

| `ANTHROPIC_API_KEY` | **yes** | Only if `AI_PROVIDER=anthropic` |

| `REPLY_REASONING_EFFORT`, `REPLY_FALLBACKS` | no | Optional provider tuning |
| `TRANSCRIPTION_PROVIDER` | no | `openai`, or empty to disable recording |
| `TRANSCRIPTION_MODEL` | no | `gpt-transcribe` (verified) |
| `TRANSCRIPTION_API_KEY`, `TRANSCRIPTION_BASE_URL` | key: **yes** | Optional separate transcription key and endpoint |
| `ELEVENLABS_API_KEY` | **yes** | Natural voice for `POST /api/speech`. Not the voice id |

### Setting a secret (value via stdin, never on the command line)

Read the value from a local file or a hidden prompt and pipe it, so it never lands in shell history, `ps`, or logs:

```sh
# Hidden prompt (zsh/bash): type or paste, press Return. Nothing is echoed.
read -rs VALUE && printf '%s' "$VALUE" | railway variable set ELEVENLABS_API_KEY --stdin -s api; unset VALUE
```

- Non-secret values can be set the same way, or as `railway variable set ELEVENLABS_MODEL_ID=eleven_v4_turbo -s api`.
- Each `variable set` triggers a redeploy unless you add `--skip-deploys`. When setting several variables, use `--skip-deploys` on all but the last.
- Check names only: `railway variables -s api --kv | cut -d= -f1`. Do not run `railway variables` without `cut`, and do not use `--json`: both print raw values.

## Deploy

From the repository root, on a checkout whose state you intend to ship (ideally clean and committed, so the deploy matches a commit):

```sh
npm run check                      # typecheck, lint, tests, repo hygiene
railway up --detach -s api         # upload and build; returns immediately
railway deployment list -s api     # wait for the new id to reach SUCCESS
railway logs -s api -b --lines 80  # build log if it fails
node scripts/railway-smoke.mjs --access-code-file .env.railway.local
```

The smoke script without `--live` makes no paid calls. Add `--live` (one small live reply, one 0.25 s WAV transcription, one 11-character speech request if ElevenLabs is configured) only when you intend to spend. Exit code is 1 if any check fails.

## Rollback

Deploys are local uploads, so "previous version" means a previous Railway deployment or a previous Git commit.

1. `railway deployment list -s api` shows ids, status and time. The active one is `SUCCESS`; earlier ones are `REMOVED`.
2. **Fastest:** in the Railway dashboard, open service `api` → Deployments, pick the last known-good deployment, and choose **Rollback**. This reuses that build's image.
3. **From Git:** check out the last good commit in a separate worktree, then `railway up --detach -s api` from there.
4. `railway deployment redeploy -s api -y` (alias `railway redeploy`) re-runs the **latest** deployment as-is. Use it after a variable change or a crash, not to go back in time.
5. Run the smoke script again after any rollback.

Variable changes are not rolled back by redeploying an old build. If a variable change caused the problem, set the old value back.

## Key rotation

The OpenAI key **must be rotated** per the brief. The same procedure works for ElevenLabs and the access code.

1. **Create** a new key in the OpenAI dashboard, scoped to the project, with a spending limit if available. Leave the old key active.
2. **Update local:** edit `.env.local` in an editor and replace the `OPENAI_API_KEY` value. Don't use `echo`, and don't paste it into chat.
3. **Update Railway** via stdin:
   ```sh
   read -rs VALUE && printf '%s' "$VALUE" | railway variable set OPENAI_API_KEY --stdin -s api; unset VALUE
   ```
   This triggers a redeploy. Wait for `SUCCESS` in `railway deployment list -s api`.
4. **Verify** that the new key works: `node scripts/railway-smoke.mjs --access-code-file .env.railway.local --live` (about 2 small paid calls), and restart `npm run dev` locally and generate one live reply.
5. **Revoke** the old key in the OpenAI dashboard. Only do this after step 4 passes, so the demo never runs with no valid key.
6. Record the rotation time (not the key) in `docs/PROGRESS.md`.

**Access code rotation.** The code is generated straight into the file and piped to Railway without being echoed. This replaces the whole file, so edit it by hand instead if it holds other lines.

```sh
umask 077; printf 'RAILWAY_APP_ACCESS_TOKEN=%s\n' "$(openssl rand -hex 12)" > .env.railway.local
sed -n 's/^RAILWAY_APP_ACCESS_TOKEN=//p' .env.railway.local | tr -d '\n' | railway variable set APP_ACCESS_TOKEN --stdin -s api
```

Open the file in an editor to read the new code, then enter it on the iPad. After the redeploy, any old code saved in the iPad's Safari `sessionStorage` stops working.

## iPad access

1. Open **https://api-production-18038.up.railway.app** in Safari. It must be HTTPS: the camera needs a secure context, and the laptop's `localhost` is not reachable from the iPad (D29).
2. In setup, type the code into **Access code for this deployment**. The app keeps it in `sessionStorage` for that tab and sends it as the `x-still-here-access` header. "✓ Access code accepted." confirms it through `/api/status`. Without a code, Fixture demo and Local only still work.
3. **Camera:** when prompted, allow camera access. Safari remembers camera permission **per site**. If it was denied, open Settings → Apps → Safari → Camera, or use the "aA" menu → Website Settings → Camera → Allow for this site, then reload.
4. **Audio:** tap **Enable audio** once per page load. iPad Safari blocks playback until a direct tap. Also check the mute switch or Control Center silence and the volume.
5. A wrong code repeated 10 times from one IP locks that IP out for up to 10 minutes. A correct code is refused during the lockout too. See the caveats below.

## Caveats

- **Single instance only.** Rate limits (`src/server/request-guards.ts`), the failed-code throttle, and the ElevenLabs daily character budget are in-memory, per process. They reset on every deploy or restart, and they would not be shared if the service were scaled to more than one replica. Keep `api` at one replica.
- **Throttle is per client IP and shared.** Railway's `X-Real-IP` is the public IP, so the laptop and the iPad on the same Wi-Fi share one throttle bucket. Every request to a paid route **without** a valid code counts as a failed attempt, including the smoke script's negative probes (2 per run, 3 once speech is configured) and other agents' probes. Running the script several times in 10 minutes can lock out the iPad. On 2026-10-24 12:20 CT the first dry run reported this IP as throttled after other probes. Don't run negative probes right before a demo.
- `/api/speech` answers `NOT_CONFIGURED` (503) **before** the access gate while no ElevenLabs key and voice are set. The 401 gate on that route can only be smoke-tested after the voice is configured.
- Speech is MP3 blob-first (D30). Latency is not measured.

## Cost controls

- Paid routes (`/api/replies` live, `/api/transcribe`, `/api/speech`, `/api/voices`) require the access code. Fixture and Local-only modes cost nothing.
- Per-IP rate limits per minute: replies 30, transcription 12, speech 20, voices 30, fixture 120.
- Bounded inputs: reply request size and length policies, `MAX_AUDIO_BYTES`, speech text of at most 500 characters, and timeouts on every provider call.
- ElevenLabs: `ELEVENLABS_DAILY_CHAR_BUDGET` per process per UTC day. Also set a **credit limit on the key** in the ElevenLabs dashboard, because the in-app budget resets on restart.
- OpenAI: set a monthly budget or usage limit on the project or key in the OpenAI dashboard. Spending limits are not recorded yet (`docs/PROJECT_BRIEF.md`).
- Railway: check `railway usage` and set a workspace usage limit if wanted. Changing usage limits is an account setting, so Liam does it.
- The smoke script spends money only with `--live`.
